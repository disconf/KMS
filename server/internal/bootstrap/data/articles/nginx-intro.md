## 它是什么

Nginx 是一个**高性能 HTTP 与反向代理服务器**，同时兼任负载均衡、缓存与静态资源服务。
事件驱动 + 非阻塞 IO 的模型让它用很少的内存就能扛住上万并发连接——这是它区别于
Apache prefork/worker 模型的根本，也是「入口层默认选 nginx」的原因。

## 解决什么问题

一台应用服务器的连接数与并发模型有限，直接把用户流量打过去既扛不住也谈不上高可用。
nginx 站在最前面做四件事：

1. **反向代理**：对外一个地址，对内按路径/域名分发给不同服务；
2. **负载均衡**：upstream 轮询/权重/一致性哈希，摘除不健康节点；
3. **TLS 终结**：证书统一在一处管理与轮转，后端只走内网明文；
4. **静态与缓存**：图片、JS 直接吐盘，接口响应可以缓存，替后端省掉大头流量。

## 架构与核心概念

| 概念 | 一句话 |
|---|---|
| master | 读配置、绑定端口、管理 worker；不处理请求 |
| worker | 真正干活的进程，数量 = CPU 核数，单线程事件循环 |
| server / location | 「监听什么域名端口」与「这条 URL 走什么逻辑」两级匹配 |
| upstream | 一组后端节点与调度策略 |
| 模块 | 代理、缓存、压缩全是编译进来的模块，发行版包与源码编译的模块集合不同 |

## 版本与生态

- **主线版（mainline）**奇偶号区分：偶数号（1.24/1.26）是稳定版，生产用偶数；
- 开源版之外有 nginx Plus（商业），运维里更常见的是「开源版 + 自编译模块」或 OpenResty；
- 需要在入口层写逻辑（鉴权、限流脚本）时，直接用 OpenResty，不必给裸 nginx 塞 Lua 模块。

## 适用与不适用

**适合**：一切 HTTP 流量入口——静态站、反向代理、负载均衡、API 网关的转发层。
**不适合**：复杂应用逻辑（那是应用服务的事）、四层高性能转发有更专的 LVS/HAProxy 可以选。
