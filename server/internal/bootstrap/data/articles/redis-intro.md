## 它是什么

Redis 是**内存键值数据库**，String/List/Hash/Set/ZSet/Stream 等十几种数据结构都放在内存里操作，
单线程命令执行（IO 多路复用），因此单实例就能做到十万级 QPS。它常被叫「缓存」，
但准确说它是**数据结构服务器**——缓存只是最常见的用法。

## 解决什么问题

关系库扛不住的读流量（热点数据）、需要微秒级响应的计数/排行、跨进程的锁与会话、
简单的消息队列（Stream/List）——这些场景的共同点是「数据小、访问密、结构简单」，
放内存里 + 数据结构原生支持，比什么方案都快。

## 架构与核心概念

| 概念 | 一句话 |
|---|---|
| 单线程命令执行 | 6.0 起 IO 多线程，但命令仍单线程——没有并发冲突，也意味着慢命令会拖住所有人 |
| 持久化 | RDB（定时快照）与 AOF（追加命令日志），两者可以共存 |
| 主从复制 | 从库全量同步 + 增量传播，读写分离的基础 |
| 哨兵（Sentinel） | 监控主库，主挂了自动提从——高可用的标准答案 |
| Cluster | 数据按 slot 分片到多节点，解决单机内存上限 |

## 版本与生态

- 7.x 是当前主线：Functions、Stream 增强、Multi-part AOF；
- **许可证注意**：7.4 起核心协议改为 RSALv2/SSPL 双许可，云厂商可用性受限；
  要宽松许可可用分支 **Valkey**（Linux 基金会维护，兼容 Redis 协议）；
- 客户端各语言都有成熟实现，服务端运维者重点关心协议层命令即可。

## 适用与不适用

**适合**：缓存、会话、计数器、排行榜、分布式锁、轻量队列。
**不适合**：大 value（百 KB 以上考虑拆分或换对象存储）、需要复杂查询/事务的数据
（回 MySQL）、把 Redis 当唯一存储而不接受持久化损耗的场景。
