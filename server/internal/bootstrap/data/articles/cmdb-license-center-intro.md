## 它是什么

CMDB 授权签发中心是一套**独立部署的商业许可证管理网站**（Go 单二进制 + 内嵌静态页），
用于为 CMDB 智能运维平台签发、下载和归档 Ed25519 离线许可证。
客户买了多少资产额度、开了哪些功能包、授权到哪天，都由这里签出的许可证说了算。

核心设计是**私钥与平台物理分离**：授权中心只保存 Ed25519 签发私钥，
正式 CMDB 平台只内置对应公钥。客户拿到的只是一段签过名的许可证文本，
在平台环境里既改不了内容也伪造不了签名——想多开额度，只能回授权中心签新证。

## 许可证格式与内容

```text
CMDB-LIC-v1.<base64url(payload)>.<base64url(Ed25519 signature)>
```

| 许可证字段 | 说明 |
|---|---|
| 许可证编号 | 每张证唯一，签发记录里可追溯 |
| 客户名称 | 客户公司或项目名称 |
| 部署实例 ID | Deployment ID，客户实例的唯一身份 |
| 商业版本 | Enterprise 或 Professional |
| 最大资产额度 | 必须大于免费版的 200 |
| 有效期 | 签发时间 + 授权天数（1~3650，0 表示永久） |
| 功能包 | 逗号分隔，如 `cmdb,monitoring,automation,knowledge` |
| 签发机构 | 由 `LICENSE_CENTER_ISSUER` 配置 |

## 核心概念

| 概念 | 一句话 |
|---|---|
| 固定密钥对 | `keys/license-private.pem` + `license-public.pem`，整个产品线一套，永不重新生成 |
| Deployment ID | 客户在「系统管理 → 授权与用量」里取的实例标识，许可证只能在对号实例激活 |
| 离线签发 | 签发全程不需要客户平台联网，许可证以文本/`.license` 文件交付 |
| 覆盖式续期 | 续期/扩容 = 签新证 → 客户导入覆盖旧证；旧证记录保留在授权中心供审计 |
| 单 JSON 存储 | `/data/licenses.json` 一个文件存全部签发记录，持久化在命名卷里 |

## 签发与激活的完整闭环

```text
客户平台（系统管理 → 授权与用量）
   │ ① 复制 Deployment ID / 下载授权申请文件
   ▼
授权中心（管理员登录）
   │ ② 录入客户、Deployment ID、版本、额度、有效期、功能包
   │ ③ Ed25519 私钥离线签名 → 生成许可证
   ▼
交付许可证（复制文本或下载 .license 文件）
   │ ④ 客户粘贴到「导入商业许可证」→ 验证并激活
   ▼
平台校验：签名 / 结构 / Deployment ID / 有效期 → 激活即时生效，无需重启
```

## 适用与不适用

**适合**：CMDB 智能运维平台的商业交付与续费管理——需要按客户实例控制
版本、资产额度和功能包的团队。

**不适合**：当成通用 License 服务器——签发私钥只对应 CMDB 平台内置的
那一把公钥；也不适合多实例高可用场景，单个 JSON 数据文件决定了它只跑单副本。
